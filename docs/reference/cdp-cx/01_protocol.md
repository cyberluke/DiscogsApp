# Sony CDP-CX S-Link Reference Specification

# 01. Physical Protocol

Version: 1.0

---

# Purpose

This document describes the physical transport used by Sony CDP-CX changers.

It intentionally ignores higher protocol layers.

Topics covered:

- Electrical interface
- Timing
- Bit encoding
- Synchronization
- Transmission rules
- Collision behaviour
- Decoder implementation

---

# Bus Overview

Sony S-Link (Control-A1 / Control-A1II)

is a

two-wire

bidirectional

open-collector

shared serial bus.

Unlike UART, there is:

- no clock
- no parity
- no checksum
- no arbitration
- no addressing at electrical level

Everything is timing based.

---

# Connector

Most CDP-CX changers expose S-Link using

3.5 mm mono jack connectors.

Multiple devices may be connected together.

The bus is electrically shared.

---

# Electrical Characteristics

Idle level

HIGH (approximately +5V)

Active level

LOW

Every device only pulls the line LOW.

No device actively drives HIGH.

HIGH is generated by pull-up resistors.

Therefore the interface behaves like

Open Collector

(Open Drain).

---

# Idle State

Normal bus:

────────────── HIGH ──────────────

Communication begins only when a participant pulls the line LOW.

---

# Time Base

Everything is based on approximately

600 µs

This is the fundamental protocol unit.

Real hardware is tolerant to small timing deviations.

---

# Bit Encoding

Three LOW pulse lengths exist.

## Synchronization

LOW

2400 µs

followed by

600 µs HIGH

Meaning:

Beginning of new frame.

---

## Logical Zero

LOW

600 µs

followed by

600 µs HIGH

Meaning:

Bit value

0

---

## Logical One

LOW

1200 µs

followed by

600 µs HIGH

Meaning

Bit value

1

# Delimiter

Every LOW pulse

must

be followed by

one delimiter

of approximately

600 µs HIGH.

There are no exceptions.

Delimiter length never carries information.

It only separates symbols.

---

# Byte Encoding

One byte consists of

8 bits.

Most Significant Bit

is transmitted first.

Example

```

10110000

```

is sent as

```

0

1

1

0

0

0

0

MSB first.

One transmission contains

two or more bytes.

```

# Inter-frame Timing

Frames are separated by idle bus time.

There is no explicit

END OF FRAME

marker.

The end of transmission is detected by timeout.

---

# Timeout Detection

Reference implementations typically use

approximately

50 ms

without additional bits

to declare the frame complete.

This approach is used by the Rolf Eigenheer gateway implementation and greatly simplifies decoding. :contentReference[oaicite:0]{index=0}

---

# Synchronization Rules

A synchronization pulse

always

starts a new frame.

A decoder should therefore

discard any partially assembled frame

when a new synchronization pulse arrives.

Never attempt to merge two synchronized frames.

---

# Bus Arbitration

Important

S-Link has

NO

bus arbitration.

Multiple devices may begin transmitting simultaneously.

Collisions

are therefore possible.

The protocol contains

no collision detection

and

no retry mechanism.

Applications must tolerate missing frames.

This behaviour is explicitly noted in the gateway documentation. :contentReference[oaicite:1]{index=1}

---

# Practical Consequences

Never assume

every transmitted frame

will be received.

Never assume

every received frame

is complete.

Never assume

every command

will generate a response.

Robust software must recover.

---

# Noise

Because decoding depends only on pulse length,

very short glitches should be ignored.

Reference implementations validate pulse duration before accepting symbols. :contentReference[oaicite:2]{index=2}

# Decoder Architecture

Recommended implementation

```

GPIO Interrupt

↓

Measure pulse width

↓

Classify

Sync

0

1

↓

Bit Builder

↓

Byte Builder

↓

Frame Builder

↓

Protocol Parser

```

Each layer should perform exactly one task.

---

# Interrupt Handler

The interrupt routine should only

- timestamp edges
- classify pulse width
- append bit
- detect timeout

Avoid

- logging
- string allocation
- parsing packets
- playlist logic
- HTTP
- JSON

All higher-level work belongs outside the ISR.

---

# Frame Builder

Responsibilities

- detect synchronization
- assemble bytes
- detect timeout
- emit completed frame

Nothing else.

---

# Protocol Parser

Responsibilities

- identify player
- identify command
- decode payload
- emit semantic event

Examples

```

TrackStarted

TrackEnded

DoorOpened

PowerOn

DiscLoaded

```

---

# Playback Runtime

The protocol parser

must never

advance playlists.

Instead

```

Protocol

↓

Playback Session

↓

Playlist Runtime

```

This separation keeps transport decoding independent from playback policy.

---

# Source of Truth

The Sony changer

is always

authoritative.

The application represents

its current interpretation

of the hardware.

If disagreement occurs,

the application

must

resynchronize.

---

# Implementation Checklist

Decoder SHOULD

✓ detect Sync

✓ decode MSB first

✓ verify delimiter timing

✓ detect timeout

✓ reject malformed frames

✓ survive collisions

✓ survive missing frames

✓ emit immutable frame objects

Decoder MUST NOT

✗ parse playlist

✗ modify UI

✗ perform networking

✗ allocate unnecessary memory

✗ block interrupt execution
